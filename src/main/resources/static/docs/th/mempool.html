₿ Bitcoin Portfolio — การเชื่อมต่อ mempool

วิธีเชื่อมต่อแอปกับอินสแตนซ์ mempool ที่คุณโฮสต์เอง และสิ่งที่จะปลดล็อกได้: ราคาปัจจุบันและการเติมราคาย้อนหลัง การติดตามที่อยู่บนบล็อกเชนพร้อมยอดคงเหลือที่แคชไว้ การเชื่อมโยงธุรกรรมบนบล็อกเชนกับรายการที่มีอยู่แล้ว และคอลัมน์ On-Chain ในตารางโพซิชัน

ส่วน A

ตั้งค่าและราคา

ทุกฟีเจอร์ที่อิงกับ mempool ในแอปนี้ — ราคา การเติมข้อมูลย้อนหลัง การติดตามที่อยู่ ลิงก์ไปยัง TXID — ต้องมีการตั้งค่าอินสแตนซ์ mempool ก่อน ก่อนหน้านั้นทุกอย่างในส่วนนี้จะถูกปิดใช้งานอยู่

ℹ ต้องเป็นอินสแตนซ์ที่คุณโฮสต์เองเท่านั้น ไม่ใช่ mempool.space: แอปจะสื่อสารกับอินสแตนซ์ mempool ของคุณเอง (เช่น แอป mempool บน Umbrel หรืออินสแตนซ์ในเครือข่ายท้องถิ่นของคุณ) ผ่าน โฮสต์:พอร์ต ธรรมดา — ไม่ได้เรียก API สาธารณะของ mempool.space โดยตรง หากคุณยังไม่มีอินสแตนซ์ Umbrel Community App Store ที่อธิบายไว้ในหน้า การใช้งานและติดตั้ง เป็นวิธีหนึ่งในการติดตั้ง

ตั้งค่าอินสแตนซ์

เปิดไอคอนรูปเฟืองที่ส่วนหัว → การตั้งค่า → หัวข้อ “การเชื่อมต่อ mempool (ไม่บังคับ)”

ฟิลด์ความหมาย
Hostชื่อโฮสต์หรือ IP ของอินสแตนซ์ mempool ของคุณ เช่น localhost หรือ IP ในเครือข่ายท้องถิ่น ไม่ต้องใส่ scheme (ไม่ต้องมี http://)
Portพอร์ตที่อินสแตนซ์ mempool ของคุณรับฟังอยู่
เว้นว่างไว้ฟีเจอร์ mempool ทั้งหมดจะถูกปิดใช้งาน — จะไม่มีการเรียกใดๆ จนกว่าจะกรอกทั้งสองฟิลด์
🔒 ความเป็นส่วนตัว: เซิร์ฟเวอร์ของแอปนี้ — ไม่ใช่เบราว์เซอร์ของคุณ — เป็นผู้เชื่อมต่อกับโฮสต์ที่ตั้งค่าไว้ ใช้เฉพาะในเครือข่ายท้องถิ่นของคุณเท่านั้น อย่าชี้ไปยังอินสแตนซ์สาธารณะที่คุณไม่ได้ควบคุม

ราคาปัจจุบันและการเติมราคาย้อนหลัง

เมื่อตั้งค่าแล้ว จะมีสามจุดที่เริ่มใช้งานอินสแตนซ์นี้:

  • ป้ายราคาที่ส่วนหัว — ไอคอน mempool เล็กๆ ข้างราคาจะดึงอัตราปัจจุบันของสกุลเงินที่แสดงผลโดยตรงจากอินสแตนซ์ของคุณ
  • มุมมอง Holdings — “เติมปีที่ขาดหายไปจาก mempool (EUR+USD)” เติมราคาอ้างอิงสิ้นปีที่ขาดหายไปจากชุดข้อมูลย้อนหลังของอินสแตนซ์คุณ
  • มุมมองรายปี — “เติมเดือนที่ขาดหายไปจาก mempool (EUR+USD)” ทำแบบเดียวกันแต่รายเดือน
ℹ การเติมข้อมูลย้อนหลังครอบคลุมเฉพาะ EUR และ USD — สกุลเงินแสดงผลอื่นๆ ไม่มีชุดข้อมูลย้อนหลังและต้องกรอกเอง จุดข้อมูลจะถูกนับก็ต่อเมื่ออยู่ใกล้วันที่เป้าหมายมากพอ (สิ้นปี/สิ้นเดือน) มิฉะนั้นช่วงเวลานั้นจะถูกเว้นว่างไว้แทนที่จะแสดงค่าประมาณที่อาจทำให้เข้าใจผิด

นาฬิกา mempool (มุมมอง Holdings)

มุมมอง Holdings ยังมีการ์ดเล็กๆ “Mempool” ที่แสดงภาพบล็อกถัดไป/ค่าธรรมเนียมแบบสด ฝังมาจากอินสแตนซ์ที่คุณตั้งค่าไว้ — พร้อมทางลัด “เปิดในแท็บใหม่” ใช้ host/port เดียวกัน ไม่ต้องตั้งค่าเพิ่มเติม

ส่วน B

ที่อยู่และยอด On-Chain

เพิ่มที่อยู่ Bitcoin หนึ่งรายการหรือมากกว่าให้กับโพซิชัน (wallet/exchange) เพื่อเปรียบเทียบจำนวน BTC ที่บันทึกไว้กับสิ่งที่อยู่บนบล็อกเชนจริง — โดยไม่ต้องออกจากแอป

เพิ่มที่อยู่

เปิดโพซิชันเพื่อแก้ไข → หัวข้อ “ที่อยู่ Bitcoin” → กรอกที่อยู่ (เช่น bc1q…) และป้ายกำกับ (ไม่บังคับ) จากนั้นกด “เพิ่มที่อยู่”

ดึงยอดคงเหลือ

แต่ละที่อยู่มีปุ่ม “ดูยอดคงเหลือ” / “ดึงข้อมูล” การดึงข้อมูลครั้งแรกจะเรียกอินสแตนซ์ mempool ของคุณและแคชผลลัพธ์ทั้งหมดไว้ — ยอดคงเหลือที่ยืนยันแล้ว ยอดคงเหลือที่ยังไม่ยืนยัน และธุรกรรมล่าสุดสูงสุด 50 รายการ เมื่อเปิดหน้าต่างอีกครั้ง ระบบจะแสดงข้อมูลที่แคชไว้นี้ทันที พร้อมเวลาที่ดึงข้อมูลล่าสุด (“ดึงข้อมูลล่าสุด”) — ไม่มีการเรียกเครือข่ายจนกว่าคุณจะรีเฟรชเอง

ฟิลด์ความหมาย
ยอดคงเหลือที่ยืนยันแล้วยอดคงเหลือบนบล็อกเชนจากธุรกรรมที่ยืนยันแล้วเท่านั้น
ยังไม่ยืนยันผลสุทธิของธุรกรรมที่ยังอยู่ใน mempool แสดงแยกต่างหาก
รับ / ส่งทิศทางและจำนวนสุทธิของธุรกรรมล่าสุดแต่ละรายการ (สูงสุด 50 รายการ)
บันทึกไว้แล้วตรวจสอบแบบสดกับรายการธุรกรรมปัจจุบันของคุณ — ไม่เคยแคชไว้ จึงไม่มีทางล้าสมัย
ℹ “ยังไม่เคยดึงข้อมูล” จะแสดงจนกว่าจะมีการดึงข้อมูลครั้งแรก — คลิก “ดึงข้อมูล” เพื่อดูสถานะบนบล็อกเชนปัจจุบัน หลังจากนั้นการดึงข้อมูลใหม่จะเป็นการตัดสินใจของคุณเสมอ ฟีเจอร์นี้จึงไม่มีทางเรียกข้อมูลเองโดยไม่มีการสั่ง

ภาพรวมที่อยู่ (ดึงพร้อมกันทั้งหมด)

สำหรับโพซิชันที่มีหลายที่อยู่ “ภาพรวมที่อยู่” จะเปิดทั้งหมดพร้อมกันทันทีจากแคช ปุ่มแยกต่างหาก “ดึงข้อมูลทั้งหมดใหม่ (สด)” จะเรียกข้อมูลใหม่สำหรับทุกที่อยู่ในครั้งเดียว

คอลัมน์ On-Chain ในตารางโพซิชัน

ตารางการจัดการข้อมูลมีคอลัมน์ “On-Chain” ซึ่งคำนวณจากยอดคงเหลือที่แคชไว้ข้างต้นเท่านั้น — ไม่มีการเรียกเครือข่ายตอนโหลดหน้า คลิกที่ค่าเพื่อไปยังภาพรวมที่อยู่ของโพซิชันนั้นโดยตรง

สถานะความหมาย
–โพซิชันนี้ไม่มีที่อยู่ผูกอยู่
⚠ บางส่วนยังไม่ได้ดึงข้อมูลของทุกที่อยู่อย่างน้อยหนึ่งครั้ง — ยอดรวมที่แสดงครอบคลุมเฉพาะที่อยู่ที่ดึงข้อมูลแล้ว
ไฮไลต์ยอดรวมบนบล็อกเชนแตกต่างจากจำนวน BTC ที่บันทึกไว้ของโพซิชันนี้ — ควรตรวจสอบ แม้จะเป็นข้อมูลบางส่วนก็ตาม
ส่วน C

เชื่อมโยงและนำเข้า

เมื่อธุรกรรมบนบล็อกเชนที่ดึงมายังไม่ถูกบันทึกไว้ คุณมีสองวิธีจัดการ — ขึ้นอยู่กับว่ามันเป็นรายการใหม่จริงๆ หรือถูกบันทึกไว้แล้วแต่ยังไม่มี TXID

เชื่อมโยงกับธุรกรรมที่มีอยู่

สำหรับทุกธุรกรรมที่ยืนยันแล้วแต่ยังไม่ถูกบันทึก แอปจะค้นหาธุรกรรม TRANSFER_IN/TRANSFER_OUT ที่มีอยู่แล้วในโพซิชันเดียวกันที่ตรงกัน: ยังไม่มี TXID จำนวน BTC ตรงกันเป๊ะ วันที่ปฏิทินเดียวกันกับธุรกรรมบนบล็อกเชน เมื่อพบรายการที่ตรงกันจะแสดง “พบธุรกรรมที่มีอยู่ซึ่งอาจตรงกัน” พร้อมปุ่ม “เชื่อมโยง”

  1. คลิก “เชื่อมโยง” ที่รายการที่ตรงกัน
  2. ระบบจะตั้งค่าเฉพาะ TXID บนบล็อกเชนให้กับธุรกรรมที่มีอยู่ของคุณ — จำนวน วันที่ โพซิชัน และอย่างอื่นทั้งหมดจะยังคงเป็นค่าที่คุณกรอกไว้เดิมทุกประการ
  3. หากมีหลายรายการที่ตรงกัน ระบบจะแสดงทั้งหมด — คุณเลือกรายการที่ถูกต้องเอง

นำเข้าเป็นธุรกรรมใหม่

ไม่พบรายการที่ตรงกัน หรือไม่มีรายการใดถูกต้อง? “นำเข้าเป็นรายการใหม่อยู่ดี” จะสร้างธุรกรรม TRANSFER_IN/TRANSFER_OUT ใหม่ทั้งหมด พร้อม TXID บนบล็อกเชนที่ตั้งค่าไว้แล้ว

ℹ การจับคู่ถูกออกแบบให้แคบโดยตั้งใจ: เฉพาะ TRANSFER_IN/TRANSFER_OUT เฉพาะโพซิชันเดียวกัน จำนวนตรงเป๊ะ วันเดียวกัน มีไว้เพื่อจับกรณีที่ชัดเจน — การเคลื่อนไหวบนบล็อกเชนที่คุณบันทึกด้วยมือไว้แล้วก่อนเพิ่มที่อยู่ — ไม่ใช่การเดาในสถานการณ์ที่คลุมเครือ
ส่วน D

TXID ในหน้าต่างแก้ไข

ทุกธุรกรรม TRANSFER_IN/TRANSFER_OUT มีฟิลด์ TXID บนบล็อกเชน (ไม่บังคับ) ในหน้าต่างแก้ไข — ตั้งค่าอัตโนมัติจากการเชื่อมโยง/นำเข้าข้างต้น หรือกรอกเอง

ฟิลด์ความหมาย
TXID บนบล็อกเชนTXID แบบเลขฐานสิบหก 64 ตัวอักษร ตรวจสอบแบบไม่เข้มงวดเท่านั้น — ค่าที่ดูไม่เหมือน TXID ที่ถูกต้องจะแสดงคำเตือน แต่ยังคงถูกบันทึกตามที่กรอกไว้
ปุ่มไปยัง mempoolเปิดธุรกรรมโดยตรงในอินสแตนซ์ mempool ที่คุณตั้งค่าไว้ จะถูกปิดใช้งานหากยังไม่ได้ตั้งค่าอินสแตนซ์

คู่ธุรกรรมโอนภายในตัวเอง

การโอนระหว่างสองโพซิชันของคุณเองคือธุรกรรมบนบล็อกเชนเดียวกันในทางกายภาพ ถูกเก็บไว้เป็นคู่ TRANSFER_OUT/TRANSFER_IN ที่เชื่อมโยงกัน ฟิลด์ TXID จะทำให้ทั้งสองฝั่งซิงค์กันอยู่เสมอ:

  • การตั้งค่า TXID ที่ฝั่งหนึ่งจะเติมให้อีกฝั่งโดยอัตโนมัติ — แต่เฉพาะกรณีที่ฝั่งนั้นยังว่างอยู่เท่านั้น ค่าที่แตกต่างกันในอีกฝั่งจะไม่ถูกเขียนทับโดยไม่แจ้งเตือน
  • การลบ TXID ที่ฝั่งหนึ่งจะลบออกจากฝั่งที่จับคู่กันด้วยเสมอ ไม่มีเงื่อนไข — ดังนั้นการลบ TXID ที่ผิดพลาดจะลบออกจากทั้งสองฝั่งของคู่เสมอ ด้วยการแก้ไขเพียงครั้งเดียว
ℹ การซิงค์นี้ทำงานเฉพาะตอนบันทึกเท่านั้น และเฉพาะระหว่างสองฝั่งของการโอนเดียวกัน — ธุรกรรมที่ไม่เกี่ยวข้องจะไม่ถูกแตะต้องเลย
