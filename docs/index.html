01 / 06

Import CSV

Use “Import CSV” to select a file. The app automatically detects the columns and suggests a mapping — e.g. for CoinTracking exports or your own files with different column names.

  • Required fields (marked *): Type, Date, Wallets & Exchanges, Buy Value, Buy Currency, Sell Value, Sell Currency must each be mapped to a CSV column.
  • Fixed Wallet / Exchange: overrides the column mapping and sets the same position for all rows — useful for files that only cover one exchange.
  • Type value mapping: every raw value found in the file (e.g. Auszahlung, Staking) is explicitly mapped to an internal type — or set to – ignore – to skip these rows on import.
ℹ Tip: Before finalizing the import, check the number of detected rows shown at the top of the dialog — if it doesn't match the source file, check whether the delimiter or header row was detected correctly.
02 / 06

The app's own CSV format

Without the CoinTracking option, the app exports in its own format. This is also the format expected by a manual CSV import when not using CoinTracking auto-mapping. 

"typ","date","exchange","buyQty","buyCur","sellQty","sellCur","fee","feeCur","comment"
"Einzahlung","20.07.2026 16:53:27","Bitbox02","0.00490000","BTC","","","","EUR","Example transfer to own wallet"
"Auszahlung","20.07.2026 16:53:26","21 Bitcoin","","","0.00500000","BTC","0.00010000","BTC","Example transfer to own wallet"
"Trade","19.07.2026 16:53:26","21 Bitcoin","0.01000000","BTC","500.00","EUR","0.00000000","EUR","Example transaction"

Important: typ controls the transaction kind — the app uses the fixed literal values Einzahlung (deposit), Auszahlung (withdrawal) and Trade, regardless of UI language. buyQty/buyCur and sellQty/sellCur describe what was bought and sold, respectively.

Add a transaction manually

Use “Add Transaction” in the dashboard header to open a form for a single entry.

ℹ Tip: Every exchange/wallet must be created once as a position before the first booking — either directly in the form or via “Add Wallet / Exchange” in the dashboard.
04 / 06

Lock the app

The lock icon in the navbar header (next to “Actions” / “Visualization”) encrypts all positions and transactions with a password and removes the plaintext data from the database. Use it whenever the app is about to be left unattended or the underlying machine isn't fully trusted.

FieldMeaning
PasswordEncryption password — required to unlock again later
Confirm passwordMust match exactly, otherwise the lock is rejected
ℹ What happens on lock: All positions and transactions are encrypted with the password and deleted from the plain database. The app then shows a blocking “App locked” dialog on every load until the correct password is entered again — this also restores the data. Wrong attempts are rate-limited with an increasing wait time.
🔒 Encryption: AES-256-GCM, key derived from the password via PBKDF2WithHmacSHA256 with 310,000 iterations and a random 16-byte salt. A random 12-byte GCM nonce is used per encryption, and the 128-bit authentication tag detects a wrong password or tampered data on unlock.
⚠ Important: There is no password recovery. If the password is lost, the encrypted data cannot be restored.
05 / 06

Reading and using the dashboard

The dashboard is divided into three areas:

  • Metrics: Performance, Total Sats, Invested, Realized, number of transactions.
  • Positions & Allocation: Table of all wallets/exchanges with balance, value and gain/loss — clicking a row filters the transaction list. The donut chart shows the allocation by wallet/exchange.
  • All Transactions: Full list. Select one or more rows via checkbox to open the action menu.

Row actions for selected transactions:

ActionMeaning
Export SelectedExport only the marked rows as CSV
Pair TransfersLink two rows (deposit/withdrawal) as a matching wallet transfer
Change wallet or exchangeChange the position afterwards
Set Exchange RateCorrect the rate to the display currency
Not a duplicateConfirm a row flagged as a possible duplicate and remove the marking
Mark as Solo TransferDeliberately mark a deposit/withdrawal that has no counterpart
DeleteRemove the selected transactions

Row color highlighting

The background color of a row in the transaction list automatically indicates one of four states:

ColorMeaning
🟠 OrangeForeign currency without exchange rate — transaction in a currency other than the display currency, exchange rate still at 1. Fix via “Set Exchange Rate”.
🟣 PurplePossible duplicate — date, type and amount match an existing transaction. Review, then confirm via “Not a duplicate” or delete the row.
🔵 BlueSolo transfer — deposit or withdrawal with no matching booking on another position, deliberately marked as a standalone entry.
🔴 Dark redRecently imported — row comes from the CSV import of the current session, for quick review right after import.

The legend directly above the table in the dashboard shows the same four colors for quick reference.
